# Контракты mock-провайдеров

Цепочка: UI → HTTP API → service → provider interfaces → synthetic PostgreSQL → immutable snapshot → чистые правила. Mock означает подставной **источник данных**, а не подмену ответа API или отключение JWT. В проекте нет HTTP-клиентов ФНС/БКИ, банковских токенов, ML SDK или live-fallback.

## Данные

Интерфейсы: `backend/src/main/java/ru/alfahackaton/provider/`; реализации: `provider/mock/`. `DemoPipelineConfiguration` регистрирует их при `demo.data-provider=mock` (`DATA_PROVIDER=mock`).

| Интерфейс | Ответ | Обязательные свойства адаптера |
|---|---|---|
| `InternalFinanceDataProvider` | Сохранённый профиль: регистрация, счёт, события руководства/полнота истории; 12 закрытых месяцев net credit turnover, внутренний месячный долг, provenance | RUB до копейки; месяцы без дублей; исключение внутренних переводов; неизвестное отдельно от нуля; даты всех составляющих; отсутствие события известно только при полной истории |
| `BkiDataProvider` | Synthetic bureau score, два окна просрочек, внешний месячный долг, provenance | Нет двойного учёта внутреннего долга; пропуск обязательного показателя остаётся null |
| `FnsDataProvider` | Синтетические флаги блокировки/банкротства/ликвидации и provenance | Nullable флаги не превращаются в false; этот mock не обращается к государственным реестрам |

Точные Java records находятся в интерфейсах; единицы/окна определены в `data-dictionary.md` и `risk-policy.md`. Внутренние и внешние месячные платежи **не пересекаются**. Если неизвестна часть, неизвестен и общий долг. Нельзя сложить внутренний платёж с БКИ, который уже включает его; seed явно следует синтетической договорённости об отсутствии пересечения.

Маркировки shipped-источников: `SYNTHETIC_INTERNAL`, `SYNTHETIC_BKI`, `SYNTHETIC_FNS`, версия `DEMO_DATA_V1`. Свежесть считается относительно asOf snapshot. Любая будущая дата компонента недопустима; устаревшая внутренняя составляющая также не скрывается за свежей.

## Snapshot и версия

`SnapshotService` читает провайдеры в транзакции создания заявки, сохраняет канонический payload/SHA-256/дату/версию/provenance. Обновление профиля после этого не меняет расчёт. `RiskEngine` не обращается к провайдерам и не читает часы. Worker проверяет сохранённую версию правил: неизвестную версию нельзя молча пересчитать новой конфигурацией.

Старые завершённые заявки без снимков сохраняются как история без выдуманного breakdown. Старая PROCESSING восстанавливается с явно помеченным `LEGACY_RECOVERY` snapshot из доступного demo-профиля.

## Demo-auth и JWT

`auth/DemoIdentityProvider` задаёт получение synthetic identity. `MockDemoIdentityProvider` разрешает три прежних userCode, выбирается AUTH_PROVIDER=mock и отдельно требует DEMO_MODE=true. `JwtTokenProvider` — сменяемый HS256 adapter создания/строгой проверки demo-сессий. `JwtAuthenticationFilter` передаёт только проверенную identity в Spring Security. CLIENT/EMPLOYEE и owner проверяются сервером независимо от frontend storage.

Новый AUTH_PROVIDER не является готовым коннектором: пока bean не добавлен, запуск останавливается. Для банковского входа будущая команда отдельно согласует transport/issuer/claims и заменит auth adapter. Здесь нет реализации реального входа или выключателя проверки подписи.

## Как расширять

1. Добавить реализацию интерфейса в отдельный package и зарегистрировать `@Bean`/`@ConditionalOnProperty` под новым явным значением. Не оставлять два одновременно выбранных bean.
2. Преобразовать входы к единицам, окнам и nullable-семантике контракта. Явно задать источник, версию, время и исключение двойного долга. Не маркировать реальные данные SYNTHETIC.
3. Добавить контрактные тесты преобразования и управляемого отказа, сохранить детерминированные mocks/core-тесты. Реальное подключение — отдельная согласованная задача.
4. Для новой предметной области нужна новая политика/маркировка. DEMO_RULES_V1 специально принимает только synthetic sources и не становится реальной кредитной оценкой простой сменой URL.

Это точки расширения хакатонного прототипа. Брокеры, реестры коннекторов, оркестраторы банковских операций и secret stores здесь не реализованы.
