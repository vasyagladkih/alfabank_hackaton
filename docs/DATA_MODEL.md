* **СУБД:** PostgreSQL 16 (с поддержкой расширенных типов, временных зон и внешних ключей).

## 2. Спецификация таблиц реляционной модели

### 2.1. Таблица `users` (Пользователи и финансовые профили)
Хранит учетные записи, роли и операционные финансовые метрики клиента в банке (по данным расчетно-кассового обслуживания, РКО).

| Колонка | Тип данных | Ограничения | Назначение поля |
| :--- | :--- | :--- | :--- |
| `id` | `BIGSERIAL` | `PRIMARY KEY` | Уникальный суррогатный идентификатор пользователя. |
| `username` | `VARCHAR(64)` | `NOT NULL, UNIQUE` | Логин учетной записи (для демо-авторизации). |
| `role` | `VARCHAR(32)` | `NOT NULL` | Системная роль: `CLIENT` или `EMPLOYEE`. |
| `company_name` | `VARCHAR(255)` | `NULLABLE` | Полное или сокращенное наименование организации / ИП. |
| `inn` | `VARCHAR(12)` | `NULLABLE` | ИНН организации (10 знаков) или ИП (12 знаков). |
| `avg_monthly_turnover_rub` | `BIGINT` | `DEFAULT 0` | Среднемесячный оборот по счету РКО за последние 6 месяцев. |
| `annual_turnover_rub` | `BIGINT` | `DEFAULT 0` | Годовой оборот компании (база для лимита кредитования). |
| `current_balance_rub` | `BIGINT` | `DEFAULT 0` | Текущий остаток на расчетном счете. |
| `months_with_bank` | `INT` | `DEFAULT 0` | Срок непрерывного обслуживания клиента в Альфа-Банке (в месяцах). |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT CURRENT_TIMESTAMP` | Дата и время регистрации пользователя в системе. |

### 2.2. Таблица `applications` (Кредитные заявки)
Центральная сущность конвейера. Фиксирует параметры запроса, результат скоринга, одобренные банком условия и текущий статус сделки.

| Колонка | Тип данных | Ограничения | Назначение поля |
| :--- | :--- | :--- | :--- |
| `id` | `BIGSERIAL` | `PRIMARY KEY` | Уникальный номер кредитной заявки. |
| `user_id` | `BIGINT` | `NOT NULL, REFERENCES users(id)` | Ссылка на владельца заявки (клиента). |
| `amount` | `BIGINT` | `NOT NULL` | Запрошенная клиентом сумма кредита (в рублях). |
| `term_months` | `INT` | `NOT NULL` | Запрошенный срок кредитования (в месяцах). |
| `purpose` | `VARCHAR(64)` | `NOT NULL` | Бизнес-цель финансирования (`REPLENISHMENT_WORKING_CAPITAL` и др.). |
| `status` | `VARCHAR(32)` | `NOT NULL` | Текущий статус заявки (`PROCESSING`, `APPROVED`, `REJECTED`, `MANUAL_REVIEW`, `SIGNED`). |
| `rejection_reason` | `TEXT` | `NULLABLE` | Мотивированная причина отказа или перевода на ручной разбор. |
| `review_reason_type` | `VARCHAR(32)` | `NULLABLE` | Код причины ручной проверки (`TECH_FAILURE`, `BORDERLINE_SCORE`). |
| `scoring_score` | `INT` | `NULLABLE` | Итоговый интегральный скоринговый балл заемщика (0–100). |
| `calculated_pdn_percent` | `DOUBLE PRECISION` | `NULLABLE` | Рассчитанный показатель долговой нагрузки (ПДН, в %). |
| `max_limit_rub` | `BIGINT` | `NULLABLE` | Максимально возможный кредитный лимит по финансовой модели. |
| `approved_amount` | `BIGINT` | `NULLABLE` | Фактически одобренная сумма кредита. |
| `approved_rate` | `DOUBLE PRECISION` | `NULLABLE` | Персональная годовая процентная ставка (16.5% – 23.5%). |
| `created_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT CURRENT_TIMESTAMP` | Время подачи заявки. |
| `updated_at` | `TIMESTAMP WITH TIME ZONE` | `DEFAULT CURRENT_TIMESTAMP` | Время последнего изменения статуса заявки. |

## 3. Регуляторный аудит и неизменяемость данных (Audit Trail)

### Почему используются отдельные таблицы снимков?
В соответствии с Положением Банка России № 590-П, коммерческий банк обязан формировать резервы на возможные потери по ссудам на основании **мотивированного суждения**, зафиксированного на момент вынесения решения.

Внешние реестры динамичны: финансовое состояние компании может измениться через месяц после выдачи кредита. Раздельное хранение неизменяемых снимков гарантирует:
1. **Воспроизводимость решения:** спустя год банк может доказать аудиторам ЦБ РФ, почему заемщику была одобрена сумма под ставку 17.5% (на основании снимков с отсутствием долгов на дату рассмотрения).
2. **Изоляция отказов:** если БКИ временно недоступен, снимок ФНС уже зафиксирован в базе и не откатывается.
3. **Безопасность персональных данных:** снимки привязаны каскадным удалением к заявке (`ON DELETE CASCADE`).
